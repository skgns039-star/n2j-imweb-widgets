# ENG-041 대화형 연결 위저드 (REQ-026~030, REQ-035 / §24)

구현: `src/bot/onboarding.ts` + `src/bot/router.ts`. 상태는 `state/threads.sqlite3` 의 `onboarding` 테이블.
런타임 기능이므로 **Hallmark 적용 대상이 아니다.** 새 라이브러리를 쓰지 않는다.

## 진입
`연결 / 연동 / 붙여줘 / setup / 셋업 / connect / /connect` → connect 라우트.
단, 위젯·슬롯·registry 등 기존 엔티티가 함께 나오면 connect가 아니다 (§24.8 → `patterns/routing.md`).

## 순서
1. **Q-OWN 소유권** (REQ-035) — A 본인 / B 위임 / C 아님·불확실
   · B는 스캔(읽기)까지만. 아임웹 쓰기는 `OPEN-BRW-01` 해소 전까지 차단.
   · C는 위저드 종료.
2. **4지선다** — A 사이트 / B 엔진 / C GitHub·CDN / D 텔레그램. 완료된 항목은 "완료됨. 변경할까요?"로 재확인만.
3. 각 분기는 독립 위저드.

## A 사이트
`kind(A1/A2/A3) → site_id(+락) → url(200) → plan → test_path(200) → [A2·A3: scan] → slots → snippet → commit`
- A2·A3는 **스캔을 건너뛸 수 없다** (REQ-031).
- 삽입 안내에는 "원문을 먼저 복사해 보관" 문구가 항상 붙는다 (INV-6).
- "삽입했어" 는 말로 끝나지 않는다. **다시 렌더해서** 로더가 실제로 있는지 확인하고, 없으면 실패로 보고한다.
- 확정(manifest 커밋)은 **1회 승인 대상** (REQ-029). 부분 완료 상태로는 절대 커밋하지 않는다 (INV-9).

## B 엔진 / C GitHub / D 텔레그램
- B: `dry_run | codex_sdk | claude_agent_sdk` 중 **하나만**. 두 개를 지목하면 거부한다 (update 단일 소유자).
  인증은 대화로 받지 않고 패키지·환경변수 존재 여부만 OK/NG로 본다.
- C: owner/repo 형식 검증 → public 확인. private면 `OPEN-REG-01` 안내 후 중단. git remote는 **명령만 출력**하고 실행하지 않는다.
- D: 봇 토큰 **존재 여부와 길이 범위만** 확인. chat_id 등록은 승인 대상.

## 비밀값 (REQ-027)
- 위저드는 토큰·키·비밀번호를 묻는 질문을 **만들지 않는다** (PTEST-038이 모든 ask()를 검사한다).
- 사용자가 보내면 값을 저장·로그·에코하지 않고 거부 + **재발급 권고**를 낸다 (`src/release/secrets.ts`).
- 이 판정은 `handle()` 진입 즉시, 다른 어떤 처리보다 먼저 일어난다.

## 상태·만료 (REQ-028 / §24.7)
| 상황 | 처리 |
|---|---|
| 15분 무응답 | 위저드 폐기 + **대기 승인 동반 무효화** |
| 승인만 15분 만료 | 위저드 유지, 승인만 재요청 |
| "취소" | 승인·위저드·락 모두 해제 |
| 정상 완료 | 상태·락만 해제. **방금 만든 승인은 유지한다** |
| "이어서" | 마지막 단계부터 재개 |
