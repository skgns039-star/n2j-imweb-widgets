# ENG-043 기존 코드 이관 절차 (REQ-032 / §24.9)

구현: `src/bot/migrate.ts`. **사용자가 명시적으로 "이관"이라고 요청할 때만** 시작한다.
기존 코드를 "정리·개선·최적화"하겠다고 **먼저 제안하지 않는다** (§24.13).

| 단계 | 내용 | 실패 시 |
|---|---|---|
| D1 | 원문 스냅샷 저장 (`state/imweb_snapshots/`) + 되읽어 해시 대조 | **착수 거부.** 스냅샷 없이 쓰지 않는다 (INV-6) |
| D2 | 원문을 `src/widgets/<id>/` 로 옮겨 정본화. **원본은 아직 지우지 않는다** | - |
| D3 | 린트·예산 검사 (CSS 스코프·전역 오염·gzip) | **위반 목록만 보고하고 중단.** 자동 수정 금지 |
| D4 | manifest에 `enabled:false` 로 등록 (1회 승인) | 승인 없으면 미반영 |
| D5 | 배포 후 사용자가 실사이트에서 신구 동시 동작 확인 | - |
| D6 | 아임웹 원본 인라인 코드 제거 (1회 승인) | 스냅샷 없으면 거부 |

## D3 — 자동 수정 금지가 핵심이다
기존 코드에 `ddak-` 접두사를 자동으로 붙이면 원래 동작이 깨진다. 그래서 린트 실패는 "고쳐주는" 대상이 아니라 **멈추는** 대상이다.
사용자가 직접 스코프를 맞춘 뒤 다시 붙여넣거나 취소한다.

## D6 — 72시간 관찰
신 위젯 배포 후 **최소 72시간** 정상 동작을 확인한 뒤에만 제거를 제안한다. 즉시 제거하지 않는다.
관찰 시간은 `logs/actions/` 의 성공 배포 기록 기준으로 센다. 미달이면 승인 페이로드 자체를 만들지 않는다.

## 중단 안전성
D1~D6 어느 단계에서 멈춰도 **아임웹은 이전 상태 그대로**다. 이 모듈에는 아임웹 쓰기 수단이 없다 —
제거는 승인 후에도 사람이 직접 수행하고, 에이전트는 스냅샷 확인·정규화 diff 검증만 안내한다.

검사: TEST-050~052 / PTEST-040.
