# 아임웹 SEO 자동화 스킬 v2.0

> 이 스킬은 `imweb-widget-agent` 프로젝트의 하위 스킬이다.
> 상위 권위는 `CODEX_BUILD_SPEC.md` §0.1이며, 이 문서는 그 아래 6층(engineering APPLY 모듈)에 위치한다.
> 원본: 오픈클로 아임웹 SEO 마스터 프롬프트 v1.0. 실행 주체·경로·승인 체계를 본 프로젝트에 맞게 재바인딩했다.

## 0. 이 스킬의 불변식

기존 INV-1~INV-9를 그대로 상속하고, SEO 전용 불변식 4개를 추가한다.

| ID | 불변식 | 깨졌을 때 |
|---|---|---|
| **INV-10** | SEO 삽입물은 `<!-- DDAK-SEO:START/END -->` 마커로 감싸고, **위젯 로더와 절대 섞지 않는다** | INV-1 붕괴, 삭제 시 로더 동반 삭제 |
| **INV-11** | **디자인모드 본문 텍스트·이미지·레이아웃은 읽기만 한다.** 개선안은 보고서로만 낸다 | 사용자 명시 요구 위반 |
| **INV-12** | 기존 SEO 설정값은 **비어 있을 때만** 채운다. 값이 있으면 덮어쓰지 않는다 | 고객 기존 자산 파괴 |
| **INV-13** | 확인되지 않은 사실(수치·후기·평점·전화·주소·인증)은 **어떤 산출물에도 넣지 않는다** | 허위표시·법적 위험 |

각 INV는 검사에 연결된다. 검사 없는 선언은 장식이므로 허용하지 않는다.

| INV | 강제 검사 |
|---|---|
| INV-10 | STEST-001 (마커 부재 시 삽입 거부), STEST-002 (로더 영역 diff = 0) |
| INV-11 | STEST-003 (디자인모드 쓰기 시도 0건) |
| INV-12 | STEST-004 (기존값 있는 필드 수정 0건) |
| INV-13 | STEST-005 (금지 표현 사전 검출 시 산출 차단) |

## 1. 입력 — 사용자는 메타 키워드만 준다

### 1.1 필수 입력 (1개)

```
메타 키워드: <사용자 입력>
```

**이것 하나면 시작한다.** 나머지는 아래 순서로 자동 확보한다.

| 항목 | 자동 확보 방법 | 실패 시 |
|---|---|---|
| 정식 도메인 | 스캔 대상 URL의 canonical에서 추출 | 사용자 1회 질문 |
| 브랜드명 | `<title>` 꼬리·JSON-LD·푸터 저작권 표기에서 추출 | 사용자 1회 질문 |
| 사이트 유형 | 메뉴 구조·상품 URL 패턴·폼 유형으로 분류 | `일반` 으로 처리 |
| 쇼핑몰 여부 | `/shop_`, 장바구니 요소 존재로 판정 | 아니오 |
| URL 목록 | sitemap.xml → 없으면 메뉴 크롤 (최대 50) | 사용자 지정 |
| 글로벌 모드 | hreflang·언어 스위처 존재로 판정 | 아니오 |
| GA4/GTM | 렌더 HTML의 `G-`/`GTM-` 패턴 | 미연결 |

> **추론값은 반드시 `[추론]` 태그를 붙여 보고한다.** 사용자가 정정할 수 있게 한다.
> 추론에 실패한 항목만 모아 **최대 4개까지** 한 번에 질문한다. 하나씩 묻지 않는다.

### 1.2 메타 키워드 처리 규칙 (원본 §2-1 계승)

- 키워드를 **임의로 다른 것으로 교체하지 않는다.**
- 브랜드명이 없으면 결합: `키워드 | 브랜드명`
- 이미 브랜드명이 있으면 중복 결합하지 않는다.
- 실제 페이지 내용과 맞지 않으면 **자동 교체 금지**, `메타 타이틀 후보 검토 필요`로 표시하고 질문.
- 검색량·난이도·CPC는 자료가 없으면 추정하지 않는다.

### 1.3 키워드 하나에서 자동 파생되는 것 (12종)

메타 디스크립션 · OG 타이틀 · OG 디스크립션 · 페이지별 SEO 문구 · 상품 제목/설명 후보 · 본문 보강안(보고만) · FAQ 후보 · CTA 개선안(보고만) · AEO 상단 요약문 · JSON-LD description · llms.txt 브랜드 설명문 · sitemap 우선순위 제안

**공통 후보 / 페이지별 후보 / 상품별 후보를 구분한다.** 공통 후보를 전 상품에 반복 삽입하지 않는다.

### 1.4 애널리틱스 사전 질문 게이트 (필수 선행)

> **GA4·GTM은 "검수"가 아니라 "설치"가 필요할 수 있는 유일한 항목이다.**
> 설치는 되돌리기가 번거롭고, 이미 있는 걸 또 설치하면 데이터가 두 배로 잡힌다.
> 그래서 **SEO 작업 전에 반드시 먼저 묻는다.** 자동 판단하지 않는다.

**순서: 자동 감지 → 결과 제시 → 질문 → 승인.** 감지 없이 묻지 않고, 질문 없이 설치하지 않는다.

**1) 자동 감지 (OBSERVE)**
렌더 HTML에서 `G-` / `GTM-` / `gtag(` / `dataLayer` 패턴을 찾고, 아임웹 데이터 연결·Header Code·Body Code 중 어디에 있는지 위치까지 특정한다. 측정 ID는 마스킹해 보고한다.

**2) 감지 결과와 함께 질문 (최대 3개)**

```
[애널리틱스 사전 확인]  모드: OBSERVE
자동 감지 결과: <GA4 G-ABC1****** / Header Code 위치 / GTM 없음>

Q-A1  애널리틱스를 어떻게 할까요?
  A 이미 연결됨 → 검수만 (중복·이벤트 점검, 설치 안 함)
  B 미연결 → 이번에 설치 (승인 후 진행)
  C 이번 작업에서 제외
  D 감지 결과가 실제와 다름 → 관리자 확인 후 재판정
  · 권장: 감지되면 A, 안 되면 B
  · A/B/C 차이: A는 아임웹 쓰기 0건, B는 Header Code 1회 쓰기, C는 GA4 섹션 전체 생략

Q-A2  (B 선택 시만) 어디에 붙일까요?
  A 아임웹 데이터 연결 기능  ← 권장. 중복 위험이 가장 낮고 되돌리기 쉬움
  B GTM 컨테이너            태그를 여러 개 관리할 계획일 때
  C Header Code 직접 삽입    다른 방법이 막혔을 때만
  · 세 곳에 동시에 넣지 않는다. 하나만 고른다

Q-A3  (쇼핑몰일 때만) 전자상거래 추적이 필요한가요?
  A 필요 (구매·장바구니·결제시작)
  B 불필요
  · A는 API Secret 입력과 이벤트 검증이 추가로 필요합니다
```

**3) 비밀값 취급**
- 측정 ID·컨테이너 ID·API Secret을 **대화로 받지 않는다.**
- 사용자가 아임웹 관리자에 직접 입력하거나 환경변수에 넣는다. 스킬은 존재 여부만 확인한다.
- 보고서에는 항상 마스킹한다: `G-ABC1******` / `GTM-AB****`

**4) 게이트 규칙**
- Q-A1에 답하기 전에는 GA4 관련 어떤 쓰기도 하지 않는다.
- `D` 선택 시 관리자 확인이 끝날 때까지 GA4 섹션을 `PENDING`으로 두고 **나머지 SEO 작업은 계속 진행한다.**
- 중복이 감지되면 **삭제하지 않는다.** `중복 정리 필요`로 보고하고 사용자 판단을 기다린다.
- 설치는 어떤 경우에도 1회 승인 대상이다. `OPERATING_APPROVED` 범위에 넣지 않는다.

→ 검사: `STEST-015` ~ `STEST-018` (§15)

## 2. 작업 모드

각 단계마다 현재 모드를 표시한다.

| 모드 | 하는 일 | 아임웹 쓰기 |
|---|---|---|
| `OBSERVE` | 관찰·캡처·추출·진단 | 0건 |
| `PLAN` | 수정안 작성, 적용 위치·위험도 분류 | 0건 |
| `DRAFT` | 실제 입력 후보 작성 | 0건 |
| `APPROVAL_REQUIRED` | 1회 승인 페이로드 제시 후 대기 | 0건 |
| `APPLY` | 승인 항목만 반영 | 승인 범위만 |
| `VERIFY` | 공개 페이지 재확인 | 0건 |

**첫 작업은 항상 `OBSERVE`다.** 수정으로 시작하지 않는다.

## 3. 디자인모드 불가침 경계 (INV-11)

사용자 요구에 따라 원본보다 강하게 제한한다.

### 절대 읽기 전용 — 승인이 있어도 수정하지 않음

- 본문 텍스트 (제목·문단·버튼 라벨)
- 이미지·갤러리 파일 자체
- 섹션 배치·순서·디자인
- 폰트·색상·여백
- 상품 상세설명
- 상품명·카테고리
- 메뉴명
- 메뉴 URL

→ 개선안은 **보고서에만** 기록한다. `13_client-delivery.md`에 "권장(미적용)"으로 남긴다.

### 승인 후 수정 가능 — SEO 설정칸만

- 메뉴별 **페이지 제목** (SEO 필드, 본문 아님)
- 메뉴별 **페이지 설명** (SEO 필드)
- 이미지 위젯의 **SEO용 대체 텍스트(ALT)** — 이미지 자체는 안 건드림
- Header/Body/Footer Code 내 `DDAK-SEO` 마커 구간

> **경계 판정 원칙:** *화면에 보이는 글자면 불가침, 검색엔진만 보는 값이면 승인 후 가능.*
> 판단이 애매하면 수정하지 말고 질문한다.

## 4. 서치엔진 등록 — 실제 가능 범위

원본에는 없던 항목이다. **엔진마다 자동화 수준이 다르다. 전부 자동이라고 말하지 않는다.**

| 엔진 | 소유확인 태그 생성 | 사이트 등록 | 사이트맵 제출 | 판정 |
|---|---|---|---|---|
| **Google Search Console** | 자동 | Search Console API (OAuth) | API | `자동 가능` |
| **Bing Webmaster** | 자동 | API 키 방식 + GSC 가져오기 | API | `자동 가능` |
| **Naver Search Advisor** | 자동 | 공개 등록 API 미확인 | 수집요청 API 확인 필요 | `브라우저 승인형` |
| **Daum (다음)** | 자동 | 검색등록 폼 제출 | 폼 | `브라우저 승인형` |

### 실행 전략 — 사람 개입 최소화

```
1단계 [자동]  4개 소유확인 메타태그를 한 블록으로 생성
              <!-- DDAK-SEO:START owner-verification -->
              google / naver / msvalidate / daum 태그 4줄
              <!-- DDAK-SEO:END -->
2단계 [승인]  Header Code에 이 블록 삽입 (1회 승인)
3단계 [자동]  GSC · Bing = API로 등록 + sitemap 제출 + 소유확인 트리거
4단계 [반자동] Naver · Daum = 브라우저가 등록 폼까지 열고 값을 채운 뒤
              최종 제출 버튼 직전에서 정지 → 텔레그램으로 알림
              사람이 확인 후 "제출" 한마디 → 브라우저가 클릭
5단계 [자동]  등록 결과 재확인, 소유확인 상태 폴링, 리포트 생성
```

**사람이 하는 일은 4단계의 확인 한 번뿐이다.** 이게 현실적으로 도달 가능한 최대치다.

### 확인 필요 (차단 게이트)

| ID | 항목 | 미해소 시 |
|---|---|---|
| SCHK-001 | GSC API OAuth 앱 등록 가능 여부 | 수동 등록 안내로 강등 |
| SCHK-002 | Bing Webmaster API 키 발급 여부 | GSC 가져오기 경로로 대체 |
| SCHK-003 | Naver Search Advisor 자동화 관련 약관 | 브라우저 자동화 중단, 수동 안내 |
| SCHK-004 | Daum 검색등록 현행 경로 | 수동 안내 |
| SCHK-005 | 아임웹이 robots.txt / llms.txt 직접 편집을 지원하는지 | 참고 문서로만 보관 |
| SCHK-006 | IndexNow 지원 엔진 범위 | 미적용 |

**하나라도 미해소면 해당 엔진은 `PENDING`으로 보고하고 나머지만 진행한다.** 전부 멈추지 않는다.

## 5. 자료 출처 우선순위

1. **공개 페이지** (렌더 후 DOM) — 방문자가 보는 최종 결과
2. **아임웹 관리자 / Open API** — 상품 SEO, 코드 영역, 데이터 연결
3. **디자인모드** — 읽기 전용 (INV-11)
4. **로컬 코드 원본** — `seo/<site_id>/custom-code/`
5. **사용자 제공 문서** — 메타 키워드, 브랜드 자료

**충돌 처리**
- 공개 ≠ 관리자 → `반영 불일치`
- 관리자 ≠ 디자인모드 → `대조 필요`
- 로컬 원본 없음 → `원본 백업 필요` (수정 보류)
- 확인되지 않은 정보는 반영하지 않는다

## 6. 산출물 경로

기존 프로젝트 구조 안에 둔다. 별도 홈 디렉터리를 만들지 않는다.

```
seo/<site_id>/
├─ 00_site-info.md          01_input-values.md       02_url-map.md
├─ 03_public-audit.md       04_api-admin-audit.md    05_design-mode-audit.md
├─ 06_product-seo-audit.md  07_code-audit.md         08_ga4-gtm-audit.md
├─ 09_seo-draft.md          10_approval-needed.md    11_apply-log.md
├─ 12_verify-log.md         13_client-delivery.md    14_internal-delivery.md
├─ 15_search-console.md     ← 4개 엔진 등록 상태
├─ custom-code/   header-code.html  body-code.html  footer-code.html
│                 json-ld-organization-website.html  json-ld-faq.html
│                 owner-verification.html  robots.txt  llms.txt
├─ snapshots/     <ts>_header.txt  <ts>_body.txt  <ts>_footer.txt
├─ screenshots/   public-pc/  public-mobile/  admin/  design-mode/  before/  after/
├─ exports/       html/  meta/  json/  csv/  reports/
└─ logs/          run-log.md  error-log.md  approval-log.md
```

- `seo/**` 전체(`exports/`, `screenshots/` 포함)를 `secretscan` 대상에 포함한다.
- 보고서 머리에 **고객사명 / 브랜드명 / site_id** 를 함께 표기한다.
- 스냅샷은 기존 `state/imweb_snapshots/` 규칙(INV-6)을 그대로 따른다.

| `최종납품` | 최종검수 + 납품본 |

### 단계

```
0  작업 기준 설정 — 메타 키워드 확인, 나머지 자동 추론, 폴더 생성
1  공개 페이지 진단 — PC/모바일 렌더, 메타·H·CTA·ALT·JSON-LD 추출
2  sitemap / robots / llms 확인
3  API·관리자 진단 — 상품 SEO 보호 분류, GA4/GTM 연결 방식
4  디자인모드 진단 — 읽기 전용 (INV-11)
5  코드 대조 — Header/Body/Footer 백업 후 중복 확인
6  SEO/GEO/AEO 초안 — 키워드에서 12종 파생
7  기술 적용안 — JSON-LD·robots·llms·소유확인 태그·GA4 정리안
8  중간검수
9  승인 요청 — 위험도·되돌림 방법 포함
10 승인 항목 반영 — 백업 → 수정 → 캡처
11 검증 — 공개 페이지 재확인
12 검색엔진 등록 (§4)
13 최종납품
```

## 8. 상품 SEO 보호 (INV-12)

**기본값은 기존값 보존이다. 자동 덮어쓰기 없음.**

5가지로만 분류한다.

| 분류 | 처리 |
|---|---|
| 기존값 유지 | 수정 안 함 |
| 비어 있음 | 신규 입력 후보 작성 → 승인 후 반영 |
| 중복 의심 | 후보만 작성, 반영 보류, 질문 |
| 상품 정보 불일치 | 후보만 작성, 반영 보류, 질문 |
| 위험 표현 포함 | 후보만 작성, 반영 보류, 질문 |

### 질문 폭탄 방지

발견할 때마다 묻지 않는다. **유형별로 묶어서 한 번에** 보고한다.

```
SEO 제목 중복 12개 / 설명 누락 8개 / 브랜드명 중복 5개 / 상품명 불일치 2개
→ 일괄 판단 요청
```

### 대량 수정

기본값 `OFF`. 필요 시 승인 요청서를 먼저 낸다 (총 상품 수 · 대상 수 · 백업 경로 · 되돌림 방법 포함).

## 9. 코드 영역 규칙

### 마커 (INV-10)

아임웹에 삽입하는 모든 SEO 코드는 마커로 감싼다.

```html
<!-- DDAK-SEO:START type=owner-verification v=1 -->
...
<!-- DDAK-SEO:END -->
```

- 마커 없는 기존 코드는 **우리 것이 아니다.** 읽고 보고만 하고 수정하지 않는다.
- 위젯 로더(`DDAK-LOADER`)와 SEO 블록은 **다른 마커**를 쓴다. 섞지 않는다.
- 삽입·갱신은 **마커 구간만 치환**한다. 파일 전체를 덮어쓰지 않는다.
- **멱등성:** 같은 type 마커가 이미 있으면 추가하지 않고 내용만 비교·갱신한다.

### 배치 규칙

| 넣는 곳 | 넣는 것 | 넣으면 안 되는 것 |
|---|---|---|
| Header Code 상단 | 소유확인 메타태그 4종 | robots.txt, llms.txt, 화면용 HTML |
| Header Code | 공통 JSON-LD | 화면용 HTML |
| Body Code | body 직후 필요 코드 | JSON-LD |
| Footer Code | body 종료 전 코드 | 소유확인 태그 |
| HTML 위젯 | 화면용 섹션·팝업 | SEO용 JSON-LD |

## 10. JSON-LD 규칙

기본값은 **Organization + WebSite 최소본**이다.

**절대 넣지 않는 것 (INV-13)**
placeholder · 작업 메모 · 미확인 로고 URL · 미확인 sameAs · 미확인 전화번호 · 미확인 주소 · 실제 FAQ 없는 FAQPage · 임의 가격/재고/평점/후기 · 미확인 인증

정보가 부족하면 `최소 버전만 가능` 또는 `정보 부족`으로 표시하고 넘어간다. **채워 넣지 않는다.**

## 11. GA4 / GTM 검수

**설치가 아니라 검수다.** 이미 연결되어 있을 수 있으므로 신규 설치를 먼저 하지 않는다.

- 같은 `G-` ID가 아임웹 데이터 연결 · Header Code · GTM에 동시에 있으면 → **삭제하지 말고** `중복 정리 필요`로 보고
- 측정 ID·컨테이너 ID는 마스킹해 출력 (`G-ABC1******`)
- 승인 전 삭제·교체 금지

## 12. 승인 게이트

기존 프로젝트 승인 모듈을 재사용한다. **별도 승인 체계를 만들지 않는다.**

### 항상 1회 승인

디자인모드 게시 · 페이지 제목/설명 수정 · ALT 수정 · Header/Body/Footer Code 수정 · JSON-LD 삽입 · robots/llms 변경 · GA4/GTM 수정 · 기존 코드 삭제 · 상품 SEO 대량 수정 · canonical 변경 · 소유확인 태그 변경 · **Naver/Daum 등록 폼 최종 제출**

### 승인 페이로드 형식

```
[승인 요청]
사이트:      작업 위치:    수정 전:      수정 후:
수정 이유:   영향 범위:    위험도:
되돌림 방법: 백업 경로:    유효 기간: 15분
```

침묵·과거 승인·계획 승인은 실행 승인이 아니다.

## 18. 상위 시스템과의 접합 (자기평가 R1에서 발견된 결함 보정)

### 18.1 브라우저 쓰기 게이트 — §19/M2 우회 금지 (D-01)

§4의 Naver·Daum 폼 자동입력은 **브라우저 쓰기**다. 상위 스펙 §19는 브라우저 자동 업로드를 **M2**로 묶어두었고 `OPEN-BRW-01~03`이 미해소다. 스킬이 이를 우회할 수 없다.

| 동작 | 게이트 |
|---|---|
| 공개 페이지 스캔 (읽기) | 허용. M0부터 가능 |
| GSC·Bing API 등록·제출 | `SCHK-001/002` 해소 시 허용. 브라우저 무관 |
| **Naver·Daum 폼 자동입력** | **M2 + `OPEN-BRW-01~03` 해소 필요.** 미해소면 `PENDING` |
| 미해소 시 대체 | 값이 채워진 **등록 안내 카드**를 텔레그램으로 전송. 사람이 직접 등록 |

> 스킬이 상위 마일스톤을 앞당기지 않는다. 검사: `STEST-021`

### 18.2 마일스톤 배치 (D-02)

| 게이트 | SEO 범위 |
|---|---|
| **M0** | 착수 안 함 (위젯 첫 왕복 우선) |
| **M1** | 진단 전용 — 1~8단계, `OBSERVE`~`DRAFT`. 아임웹 쓰기 0건 |
| **M2** | 9~11단계 반영 + Naver·Daum 폼 자동입력 |
| **M3** | 12~13단계, 정기 회귀 감시 |

**M1만으로도 가치가 성립한다.** 진단 보고서와 삽입용 스니펫을 받아 사람이 붙이면 된다.

### 18.3 site_id 정본 (D-06)

`seo/<site_id>` 의 `site_id` 는 **`manifest/widgets.yaml` 의 값을 그대로 쓴다.** 새로 만들지 않는다.
manifest에 없는 site_id로 SEO 작업을 시작하면 거부하고 연결 위저드(§24)를 먼저 안내한다. 검사: `STEST-022`

### 18.4 SEO 롤백 (D-09)

INV-9 fail-closed만 있고 되돌리기가 없었다. 3단계로 정의한다.

| 대상 | 롤백 |
|---|---|
| `DDAK-SEO` 마커 구간 | 마커 구간만 제거 또는 이전 버전으로 치환. 주변 코드 무변경 |
| 마커 밖 (페이지 제목/설명, ALT) | 반영 전 값을 `snapshots/<ts>_fields.json` 에 저장 → 그 값으로 복원 |
| 검색엔진 등록 | **롤백 불가.** 등록은 되돌리지 않는다. 되돌릴 수 없음을 승인 페이로드에 명시 |

`11_apply-log.md` 에 항목별 `되돌리기 방법`을 반드시 기록한다. 기록 없는 반영은 실패로 처리한다. 검사: `STEST-023`, `STEST-024`

### 18.5 승인 만료 정합 (D-07)

소유확인 폴링은 수 분~수 시간이 걸린다. 15분 승인과 충돌한다.

- **승인은 "실행 시작"에 대해 유효하다.** 시작 후 진행 중인 폴링은 만료로 중단되지 않는다.
- 폴링 중 **추가 쓰기가 필요해지면 새 승인**을 받는다.
- 폴링 상한 24시간. 초과 시 `소유확인 대기`로 남기고 종료.

### 18.6 산출물 품질 게이트 — 수치 기준 (D-03, D-04)

"너무 길거나 짧으면"은 강제할 수 없다. 수치로 고정한다.

| 항목 | 기준 | 위반 시 |
|---|---|---|
| 메타 타이틀 | 15~60자 (한글 기준) | `조정 후보`로 표시 |
| 메타 디스크립션 | 70~160자 | `조정 후보` |
| OG 타이틀 | 60자 이내 | `조정 후보` |
| OG 디스크립션 | 200자 이내 | `조정 후보` |
| ALT | 125자 이내, 파일명·"이미지" 단독 금지 | 재작성 |
| 브랜드명 반복 | 한 문자열 내 1회 | 중복 제거 |
| 동일 메타 타이틀 | 사이트 내 2개 이상 페이지 금지 | 카니발라이제이션 경고 |
| 금지 표현 | 0건 (vocabulary §2 사전) | **산출 차단** |
| placeholder | 0건 | **산출 차단** |

기준 초과는 경고이고, 금지 표현·placeholder는 **차단**이다. 검사: `STEST-025`

### 18.7 드리프트 감시 (D-05)

`03_public-audit.md` 를 실행 회차별로 보관하고, 재실행 시 직전 회차와 비교한다.

**감시 대상:** title · description · canonical · OG · JSON-LD 존재 · `DDAK-SEO` 마커 존재 · 소유확인 태그 4종 · GA4 측정 ID 개수

**마커 유실 감지 시** 즉시 알림. 아임웹 정기 업데이트로 Header Code가 초기화되는 사례에 대응한다. 위젯 회귀 감시(ENG-028)에 얹어 비용을 0으로 만든다. 검사: `STEST-026`

### 18.8 검사 실체화 (D-08)

`STEST-001~026` 은 문서 선언이 아니라 **실제 테스트 파일**로 존재해야 한다.

- 구현 경로: `tests/seo/*.test.ts`
- `npm test` 에 포함되어 기존 회귀와 함께 돈다
- 선언만 있고 테스트가 없는 STEST가 1건이라도 있으면 **빌드 실패**로 처리한다
- Ponytail 보호 목록에 `P-16: STEST 구현을 축소하지 않는다` 추가
