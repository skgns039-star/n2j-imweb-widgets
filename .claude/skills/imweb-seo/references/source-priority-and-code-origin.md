## 1. 비밀값 보호 — 대상 목록 (원본 §0-3)

아래는 **어떤 경우에도 출력하지 않는다.**

비밀번호 · 인증번호 · API Key · Access Token · Refresh Token · Service Role Key · Secret · 세션 쿠키

**읽는 위치:** 환경변수 또는 로컬 보안 파일에서만. 대화·화면·로그·저장소를 경유하지 않는다.

**마스킹 규칙**

| 원본 | 출력 |
|---|---|
| `G-ABC1234567` | `G-ABC1******` |
| `GTM-ABCDE12` | `GTM-AB****` |
| `sk_live_xxxxx` | `sk_live_****` |
| 세션 쿠키 | 값 전체 생략, 존재 여부만 |

보고서·스크린샷·로그 전부에 적용한다. 스크린샷에 값이 찍혔으면 저장 전에 마스킹하거나 파기한다.

## 2. 자료 출처별 확인 항목 (원본 §5 전량)

### 1순위 — 공개 페이지 (방문자가 보는 최종 결과)
PC 화면 · 모바일 화면 · 렌더링 HTML · title · meta description · canonical · OG · H1/H2/H3 · CTA · 이미지 ALT · JSON-LD · 내부 링크 · 외부 링크 · 상품 정보 · FAQ · robots 차단 여부

### 2순위 — 아임웹 관리자 / Open API
상품 SEO · 상품명 · 상품 설명 · 상품 카테고리 · **상품 노출 상태** · 데이터 연결 · GA4/GTM/Google Tag 상태 · robots.txt · llms.txt · Header Code · Body Code · Footer Code

### 3순위 — 디자인모드 (읽기 전용, INV-11)
메뉴별 페이지 제목 · 메뉴별 페이지 설명 · 메뉴 URL · 접속 권한 · 이미지 위젯 ALT · 갤러리 위젯 ALT · HTML 코드 위젯 위치 · 본문 섹션 구조 · CTA 위치 · PC/모바일 표시 차이

### 4순위 — 로컬 코드 원본
Header Code 원본 · Body Code 원본 · Footer Code 원본 · HTML 위젯 코드 원본 · **팝업 코드 원본** · JSON-LD 원본 · CSS/JS 원본

### 5순위 — 사용자 제공 문서
메타 키워드 · 키워드 자료 · 브랜드 설명 · 고객 요구사항 · 관리자 캡처 · 기존 납품 문서

> 상위 순위가 하위를 이긴다. 단 **확인되지 않은 정보는 어느 순위에서도 반영하지 않는다.**

## 3. 디자인모드 접근 전 환경 점검 (원본 §8-1 재바인딩)

원본은 맥미니 크롬 전제였다. 본 프로젝트는 Windows + Playwright이므로 아래로 대체한다.

| 원본 (macOS) | 본 프로젝트 |
|---|---|
| 크롬 로그인 상태 | Playwright storageState 유효성 |
| 아임웹 관리자 접속 상태 | 관리자 페이지 200 + 로그인 마커 |
| 디자인모드 진입 가능 여부 | 동일 |
| 화면 기록 권한 | 스크린샷 저장 경로 쓰기 권한 |
| 손쉬운 사용 권한 (macOS 접근성) | **해당 없음.** Playwright가 DOM으로 직접 제어 |
| 클릭/키보드 제어 가능 여부 | 셀렉터 헬스체크 통과 여부 |
| 게시 전 사용자 승인 필요 상태 | 승인 모듈 연결 확인 |

접근 실패 시: `디자인모드 접근 실패` 기록 → 공개·API 진단 계속 → 확인 필요 항목 목록화 → 스크린샷 필요 위치 기록 → 수정 보류 → 사용자에게 확인 위치를 보고서로 정리

## 4. 커스텀 코드 원본 관리 규칙 (원본 §12 전량)

아임웹에 삽입되는 모든 커스텀 코드는 **로컬 원본을 기준으로** 관리한다. 아임웹 화면에서만 추정하지 않는다.

**경로:** `seo/<site_id>/custom-code/`

### 규칙

1. 신규 삽입 코드에는 **주석 마커**를 반드시 붙인다 → `<!-- DDAK-SEO:START type=... v=... -->` ~ `<!-- DDAK-SEO:END -->`
2. 기존 코드에 마커가 없으면 **우리 것이 아니다.** 바로 수정하지 말고 먼저 백업한다.
3. 코드 삭제 전에는 반드시 기존 코드를 로컬에 저장한다.
4. Header/Body/Footer Code **전체를 백업하지 않고** 수정하지 않는다.
5. 코드에 API Key·Secret·토큰이 있으면 출력하지 말고 마스킹한다.
6. 코드 위젯의 **화면용 HTML/CSS/JS와 SEO용 JSON-LD를 섞지 않는다.**
7. JSON-LD는 가능하면 Header Code 후보로 분리한다.
8. 팝업·CTA·디자인용 코드는 HTML 위젯 또는 페이지 코드 위젯으로 분리한다.
9. **아임웹 기본 기능으로 가능한 항목은 코드로 억지 구현하지 않는다.**
10. 위젯 로더 마커(`DDAK-LOADER`)와 SEO 마커(`DDAK-SEO`)는 서로 다른 마커이며, 같은 함수로 처리하지 않는다. (INV-10)

> 9번은 Ponytail 원칙과 동일하다. 아임웹이 제공하는 SEO 설정칸이 있는데 Header Code로 우회 구현하지 않는다.

## 5. 작업 폴더 — exports 복원 (원본 §6)

```
seo/<site_id>/
├─ 00_site-info.md … 15_search-console.md
├─ custom-code/
├─ snapshots/
├─ screenshots/   public-pc/  public-mobile/  admin/  design-mode/  before/  after/
├─ exports/       html/  meta/  json/  csv/  reports/     ← 복원
└─ logs/          run-log.md  error-log.md  approval-log.md
```

**exports 용도**

| 폴더 | 내용 |
|---|---|
| `html/` | 렌더링 HTML 원본 (URL별) |
| `meta/` | 메타 태그 추출 결과 |
| `json/` | JSON-LD 추출·후보 |
| `csv/` | 상품 SEO 일괄 검토용 표 (대량 판단 시 필수) |
| `reports/` | 생성된 보고서 사본 |

`exports/**` 도 `secretscan` 대상에 포함한다. 렌더 HTML에 측정 ID·토큰이 섞일 수 있다.

## 6. 최종납품 12단계 세부 (원본 §21)

산출물은 5종이다. 하나라도 빠지면 납품 완료가 아니다.

1. 클라이언트 전달용 요약본 (`13_client-delivery.md`)
2. 내부 작업자용 상세본 (`14_internal-delivery.md`)
3. 실행 로그 (`logs/run-log.md`)
4. **보류 / 추후 작업 목록** — INV-11로 미적용된 권장사항 포함
5. **관리자 확인 필요 항목**

추가로 아래를 명시한다.

- **재점검 일정 권장** — 기본 3개월. 아임웹 정기 업데이트로 Header Code 태그가 유실될 수 있으므로, 위젯 회귀 감시(ENG-028)에 SEO 태그 존재 확인을 함께 얹는 것을 권장한다.
- 보고서 머리에 **고객사명 / 브랜드명 / site_id**를 함께 표기한다. `site_id`만 쓰면 클라이언트 전달본에서 식별이 안 된다.
